# rabi v8.0.0

Draft release notes.

## Highlights

rabi v8 turns isolated Git workspaces into a software-factory CLI. Record intent
with `rabi task new`, create its linked checkout and launch `task implement`, then
let `rabi task advance [--wait]` drive prechecks, draft PR publication, CI, review,
classification, approval/auto-merge and safe cleanup. Each step has deterministic
guards and durable evidence; agents edit, check and commit locally.

- Trusted committed prechecks run before publication. Rabi verifies the recorded
  GitHub destination, pushes without force and creates or reuses a draft PR.
- CI gates match exact-head check names and app issuers from base policy. Bounded
  feedback, a shared fix budget and repeated-failure detection stop retry loops.
- Restricted reviewers use fresh detached checkouts at the verified PR head.
  A pass marks the PR ready and upserts sanitized findings; revisions return to
  implementation. Review output never approves.
- Tool-less classification applies the written base-commit policy. Missing or
  failed assessments and uncertainty escalate to high; deterministic floors
  cannot be lowered by an agent.
- Merges require fresh preflight and `--match-head-commit`. Cleanup retains dirty,
  stashed or unpushed workspaces and all local branches; remote deletion is opt-in.
- Existing workspace and parent-session workflows remain available. Trusted
  primary-checkout `[env]` declarations share toolchain wiring for run and exec.

The [quick start](../../README.md#quick-start) shows configuration and the first task.

## Breaking changes

Read [Upgrading to v8](../upgrading-to-v8.md) for migration steps for every
[Unreleased breaking change](../../CHANGELOG.md#unreleased), including:

- Repository registration, the registry, fuzzy repository selection, ghq discovery,
  cross-repository list output and registry-based completion are removed. Use one
  current or explicitly selected repository per invocation. Clone no longer registers.
- `rabi skill` discovery is removed; `run --skill` remains optional and verbatim.
- Run parents share the task credential boundary and stricter provider restrictions.
  Codex validates linked Git metadata; newly created Cursor policies allow no network.
- Task publication requires a matching GitHub HTTPS/SSH destination. New precheck,
  review, factory and environment configuration requires upgraded binaries.
- Classification supports only tool-less Claude. `task merge` performs a merge by
  default; use `--dry-run` to evaluate without writes. Real gate refusals exit 4.

## New commands

| Commands | Purpose |
|---|---|
| `rabi task new`, `list`, `show`, `abandon` | Record intent, reserve a branch, inspect state/events and retire local bookkeeping |
| `rabi task implement` | Launch one local implementer in an existing linked task checkout |
| `rabi task advance` | Drive steps through merge and cleanup; `--wait` polls CI/approval |
| `rabi task publish` | Run prechecks and publish/reconcile a draft PR |
| `rabi task review` | Review the exact PR head and mark passing work ready |
| `rabi task risk`, `classify` | Inspect path risk or record a written-policy assessment |
| `rabi task status`, `merge --dry-run` | Read PR facts or evaluate merge gates without writes |
| `rabi task approve` | Let a configured maintainer record approval for an exact full HEAD SHA |
| `rabi task merge` | Execute a head-guarded merge after preflight |
| `rabi doctor` | Read-only GitHub diagnostics and workflow filenames for manual inspection |

See [commands and task states](../commands.md). Exit 10 means CI or maintainer
approval is waiting; 4 means refusal/blocked. Exit 0 can mean a single successful
step, not a completed task. JSON preserves reports on waiting and blocked outcomes.

## Safety model

Agents only edit, check and commit locally. Deterministic rabi commands publish
and merge outside those sessions. The shared launch boundary strips inherited
GitHub/SSH/Git credentials, uses empty gh configuration, disables Git credential
helpers/prompts and sets `RABI_AGENT=1`. Codex has network/web disabled and narrow
local Git grants; Claude implementation/run denies push/gh/web tools; classification
has no tools. Reviewers have restricted read access in fresh checkouts.

Policy and the written classification document come from base commits. Required
CI, policy freshness, earned review, classification, heads and mergeability are
rechecked before merge. Only explicitly configured low/medium auto tiers without
floors skip approval. Other changes require a configured maintainer's latest
successful `rabi/approval` status on the exact HEAD SHA. Automation never runs
`task approve`, clears the agent marker to bypass it, or posts success approval.
A new head invalidates earlier approval.

These controls prevent skipped steps and reduce accidental credential use. They
are not access control against a determined process running as the same user.
Use independent credentials and repository permissions for adversarial isolation.
See [safety and limits](../safety.md) before unattended use.

## Install

Install from GitHub Releases with `curl` and `tar`:

```sh
curl -fsSL https://github.com/yoiailabs/rabi/releases/latest/download/install.sh | sh
```

The installer verifies SHA-256 and installs to `~/.local/bin` without sudo. Linux
and macOS x64/arm64 are supported; use Linux binaries in WSL. For reproducibility,
use the published tag's installer URL and matching `RABI_VERSION`; optional
`--verify-attestation` verifies provenance with gh. See [installation](../installation.md).
